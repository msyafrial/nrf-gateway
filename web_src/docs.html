BLE Telemetry Frame Specification (44-Byte Binary)

Gateway streams raw BLE advertisement frames packed into fixed 44-byte binary records.

0..3Timestamp4 Bytes
4..9MAC6 Bytes
10PDU1 Byte
11RSSI1 Byte
12Length1 Byte
13..43Advertising Payload31 Bytes
OffsetField NameSizeData TypeDescription
0Timestamp4 Bytesuint32_t BEUnix Epoch timestamp (seconds since 1970). Converted transparently to ISO wall-clock.
4MAC Address6 Bytesuint8_t [6]BLE peripheral MAC address (Big-Endian AA:BB:CC:DD:EE:FF).
10PDU Type1 Byteuint8_tBluetooth Core Spec PDU Type (0: ADV_IND, 1: ADV_DIRECT_IND, 2: ADV_NONCONN_IND, 3: SCAN_REQ, 4: SCAN_RSP, 5: CONNECT_IND, 6: ADV_SCAN_IND).
11RSSI1 Byteint8_tPhysical received signal strength indicator in dBm (-128 to +127).
12Length1 Byteuint8_tValid advertising payload length (0 to 31 bytes; 0 for empty SCAN_RSP frames).
13AD Payload31 Bytesuint8_t [31]Raw BLE advertisement / scan response payload data (zero-padded).
QoS 1Delivery Guaranteed: Broker returns PUBACK. Recommended for mission-critical telemetry over Ethernet.
QoS 0Fire & Forget: Zero-overhead instant transmission. Optimized for high-throughput live beacon tracking.

Gateway Heartbeat Keep-Alive
 The gateway emits periodic keep-alive pings to the authoritative channel ar/hb every 30 seconds. The payload contains the gateway's unique device ID string, allowing backend watchdogs to verify that the scanner loop and network stack remain operational. 
ParameterSpecificationDescription
Topicar/hbAuthoritative broadcast keep-alive channel
Interval30 secondsPeriodic transmission frequency
Payload"%device_id%"Plaintext device ID string
Use CaseWatchdog AlertingDetect link dropouts and trigger failover alarms
